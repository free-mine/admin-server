# OreVein Admin Server

Backend панели владельца Free Mine в Avalanche C-Chain (chainId 43114).
Готовит планы операций, после подтверждения подписывает и последовательно
исполняет транзакции, отдаёт статусы через REST и WebSocket. Поддерживает
OreVein/FreeMine, преемников, Aave, LFJ и Uniswap V3. Капитал и NFT остаются
у OreVein, газ оплачивает кошелёк владельца.

API: [Swagger UI](https://free-mine.github.io/admin-server/) и
[OpenAPI](swagger/openapi.yml).

## Запуск

Нужны HTTP(S) `RPC_URL` Avalanche C-Chain, разрешённый домен `ALLOWED_DOMAIN`
и PIN входа `PANEL_PIN`. Сервер рассчитан на один экземпляр на кошелёк.

Задайте переменные в окружении и запустите контейнер:

```sh
docker run --detach --name ore-vein-admin-server \
  --publish 127.0.0.1:3000:3000 \
  --volume ore-vein-data:/app/data \
  --env RPC_URL \
  --env ALLOWED_DOMAIN \
  --env PANEL_PIN \
  ghcr.io/free-mine/admin-server
```

При `ALLOWED_DOMAIN=localhost` API доступен на `http://localhost:3000`.
Для другого домена настройте его разрешение в адрес сервера. Контейнер слушает
порт `3000` и работает от пользователя `node` (UID 1000); пример публикует порт
только на локальном интерфейсе. Для удалённого доступа используйте HTTPS reverse
proxy, сохраняющий исходные `Host` и `Origin`.

### Домен и вход

`ALLOWED_DOMAIN` содержит одно имя хоста, например `localhost` или `admin.example.com`:
без схемы, порта, пути, завершающей точки, подстановок или списка доменов.
Регистр приводится к нижнему; порты не ограничиваются. `PANEL_PIN` — строка
из 4–32 цифр; начальные нули сохраняются. PIN проверяет сервер, в клиентскую
сборку он не попадает.

HTTP и WebSocket проверяют имя хоста из `Host` и, если он есть, из `Origin`.
Оба должны точно совпадать с настроенным доменом, включая запросы к `/health`;
поддомены и альтернативные адреса не разрешены.

`POST /v1/session` с JSON `{ "pin": "ваш PIN" }` выдаёт HttpOnly cookie на 12 часов.
Она нужна для API, включая `/ready` и WebSocket; `/health` доступен без входа.
Выход отзывает сессию и закрывает её WebSocket-соединения. Перезапуск сервера
сбрасывает все сессии.

После пяти неверных PIN вход блокируется до конца 15-минутного окна, начатого
первой попыткой. Ограничение общее для процесса; успешный вход сбрасывает счётчик.

Для Swagger `Try it out` раздайте каталог `swagger/` HTTP-сервером и откройте его
через тот же домен и схему, что и API; порт может отличаться. Задайте адрес API
в `Servers`, затем выполните `POST /v1/session`. Swagger отправляет cookie
автоматически. GitHub Pages подходит для чтения документации.

### Ключи и режим чтения

`PRIVATE_KEY` — ключ текущего владельца OreVein: 64 шестнадцатеричных символа
с необязательным `0x`. Для исполнения добавьте `--env PRIVATE_KEY` к команде.
Ключ хранится только на сервере.

Без корректного ключа владельца сервер запускается в read only: доступны
чтение, WebSocket и preview, включая симуляцию от адреса владельца. Исполнение
и восстановление отправки приостановлены, файлы журнала не изменяются.
Режим виден в `readOnly` у `/v1/config` и `/ready`; для его смены нужен перезапуск.
При рабочем RPC `/ready` возвращает `200` и в режиме чтения.

### Настройки

| Переменная            | По умолчанию       | Назначение и диапазон                  |
| --------------------- | ------------------ | -------------------------------------- |
| `HOST`                | `0.0.0.0`          | Адрес прослушивания внутри контейнера. |
| `LOG_BLOCK_RANGE`     | `10`               | Блоков на запрос событий: 1–10.        |
| `DEPLOYMENT_BLOCK`    | Блок развёртывания | Начальный блок поиска событий, ≥ 0.    |
| `POLL_INTERVAL_MS`    | `3000`             | Опрос транзакций, мс: 100–60000.       |
| `PREVIEW_TTL_SECONDS` | `120`              | Срок действия плана, с: 30–600.        |
| `RPC_TIMEOUT_MS`      | `20000`            | Таймаут RPC, мс: 1000–120000.          |

## Журнал и восстановление

Полные операции, подписи и receipts записываются в `/app/data/operations.json`.
Подпись сохраняется на диск до отправки транзакции; завершённые операции остаются
в журнале. После перезапуска сервер проверяет receipts незавершённых операций
и при необходимости повторно отправляет ту же подпись с теми же nonce и хэшем.
Неподтверждённые preview хранятся только в памяти.

`GET /v1/journal` возвращает состояние хранения. Ошибка записи останавливает
исполнение, `/ready` возвращает `503`. При конфликтующих копиях или некорректных
данных сервер отказывается запускаться, сохраняя файлы для разбора.
Для подтверждённой внешней замены транзакции используйте
`POST /v1/operations/{id}/resolve`.

Сохраняйте volume при обновлении и делайте его резервные копии: потеря volume
означает потерю журнала. Старый `operations.pending.json` автоматически
переносится при запуске в режиме записи и удаляется только после сохранения
в новом журнале. В read only оба формата читаются без изменения файлов.
Записи, которые прежняя версия уже отправила на публичный сервер и удалила
локально, автоматически не загружаются; для сохранения прежней полной истории
нужен её отдельный перенос до перехода.

Чтение и исполнение используют RPC; публичный сервер больше не используется.
Переменные `PUBLIC_SERVER_URL`, `PUBLIC_SERVER_KEY`, `PUBLIC_SERVER_TIMEOUT_MS`
и `SYNC_INTERVAL_MS`, маршруты `/v1/state`, `/v1/state/refresh` и `/v1/sync` удалены.

## Разработка

Node.js 24 (от 24.13.1). После `npm ci`:

```sh
npm run lint
npm run format:check
npm run check
npm test
npm run build
```

Эти проверки выполняются в CI для каждого PR. `npm run dev` запускает сервер
с отслеживанием изменений; ему нужны те же переменные окружения.
