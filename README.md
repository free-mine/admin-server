# OreVein Admin Server

Backend панели владельца Free Mine для Avalanche C-Chain (chainId 43114).
Сервер готовит план операции, после подтверждения подписывает и последовательно
выполняет транзакции, сохраняет журнал и отдаёт статусы через REST и WebSocket.
Поддерживаются управление OreVein/FreeMine, преемники, Aave, LFJ и Uniswap V3.
Капитал и NFT позиций остаются у OreVein, газ оплачивает кошелёк владельца.

Docker-образ: **`ghcr.io/free-mine/admin-server`**. GitHub Actions собирает
и публикует его при обновлении `main`.

Техническую документацию читайте в [Swagger UI](https://free-mine.github.io/admin-server/):
начните с общего описания форматов и порядка работы, затем смотрите параметры,
примеры и ответы нужного endpoint. WebSocket описан в `/v1/ws`.
[swagger/openapi.yml](swagger/openapi.yml) — та же спецификация для редакторов
OpenAPI и генераторов клиентов; Pages показывает версию из `main`.

Сервер рассчитан на локальный доступ без авторизации: один экземпляр на кошелёк.
Порт сервера всегда `3000`, каталог данных — `/app/data`; журнал хранится в
`/app/data/operations.json`. Подключайте к этому каталогу постоянный Docker volume.
Контейнер работает от пользователя `node` (UID 1000).

Для запуска достаточно `RPC_URL` — HTTP(S) URL RPC для Avalanche C-Chain (chainId 43114).
Задайте его в окружении своей оболочки, затем запустите контейнер:

```sh
docker run --detach --name ore-vein-admin-server \
  --publish 127.0.0.1:3000:3000 \
  --volume ore-vein-data:/app/data \
  --env RPC_URL \
  ghcr.io/free-mine/admin-server
```

API будет доступен по адресу `http://localhost:3000`. Внешний порт можно изменить
через Docker, например `--publish 127.0.0.1:8080:3000`; внутри контейнера остаётся `3000`.

Для выполнения транзакций задайте `PRIVATE_KEY` в окружении оболочки и добавьте
`--env PRIVATE_KEY` к команде запуска. Нужен ключ текущего владельца OreVein:
64 шестнадцатеричных символа, префикс `0x` необязателен.

Если ключ отсутствует, пуст, некорректен или принадлежит другому кошельку, сервер
запускается в режиме read only. Доступны чтение данных, WebSocket и подготовка
preview с симуляцией и оценкой газа от адреса владельца контракта. Сервер не
подписывает и не отправляет транзакции, в том числе сохранённые в журнале.
`POST /v1/operations` и `POST /v1/operations/{id}/resolve` возвращают `403 READ_ONLY`.
Существующий журнал доступен для чтения, очередь приостановлена, файлы не изменяются;
при отсутствии каталога данных сервер работает с пустой историей.

Интерфейс определяет режим по `readOnly` в `GET /v1/config` и `GET /ready`.
При рабочем RPC `/ready` возвращает `200` и в режиме read only. Поле `owner` —
адрес владельца из контракта при запуске, а не адрес переданного ключа.
Режим определяется при запуске; для его изменения перезапустите сервер с нужным ключом.
Ошибки RPC, неверная сеть и несоответствие контрактов по-прежнему считаются ошибками.

Дополнительные переменные можно передать через `--env ИМЯ=значение`:

| Переменная            | По умолчанию                  | Назначение и допустимые значения                                       |
| --------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| `HOST`                | `0.0.0.0`                     | Адрес прослушивания внутри контейнера.                                 |
| `LOG_BLOCK_RANGE`     | `2000`                        | Размер диапазона блоков при чтении событий преемников: от 1 до 100000. |
| `DEPLOYMENT_BLOCK`    | Блок транзакции развёртывания | Начальный блок поиска событий преемников; целое число ≥ 0.             |
| `POLL_INTERVAL_MS`    | `3000`                        | Интервал опроса статуса транзакций в миллисекундах: от 100 до 60000.   |
| `PREVIEW_TTL_SECONDS` | `120`                         | Срок действия плана операции в секундах: от 30 до 600.                 |
| `RPC_TIMEOUT_MS`      | `20000`                       | Таймаут RPC-запроса в миллисекундах: от 1000 до 120000.                |

HTTP и WebSocket принимают браузерные запросы только с `http://localhost` и
`https://localhost` на любом порту. Открывайте интерфейс именно на `localhost`:
`127.0.0.1`, поддомены и другие домены в Origin не разрешены. Запросы без Origin
(например, из CLI) разрешены.

Swagger UI на GitHub Pages служит для чтения документации. Для `Try it out`
раздайте каталог `swagger/` локальным HTTP-сервером, откройте его через `localhost`
на любом свободном порту и укажите адрес API в поле `Servers`.

Для разработки нужен Node.js 24.13.1: `npm ci`, затем `npm run lint`,
`npm run format:check`, `npm run check`, `npm test` и `npm run build`.
Эти проверки выполняются для каждого PR; Swagger публикуется на Pages из `main`.
